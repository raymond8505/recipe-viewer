# NutritionFactsLabel

**ONE Nutrition Facts label, shared by both surfaces** — `src/components/nutrition/NutritionFactsLabel.tsx` + `labelRows.ts`. The catalog editor's drawer (`NutritionFactsPreview`) and the recipe panel both render it; there is no second label component. Don't re-fork it.
- **The shared type is the ROW LIST, not either nutrition type.** The drawer holds `IngredientNutrition` (snake_case per-100g, has minerals, no unsaturated fat) and the panel holds `NutrientValues` (camelCase `NutrientValue`s, has unsaturated fat, no minerals) — converting either into the other drops nutrients one way or the other. Each surface instead adapts into `LabelData` (`ingredientNutritionRows` / `recipeNutritionRows`), which is lossless because a row already carries its own name, unit and absent-state. This also makes the FDA wording (`SLOTS` in `labelRows.ts`) a single source of truth, so it can't drift between the two.
- **`layout="vertical" | "tabular"`, ONE markup.** Tabular is the FDA tabular display (identity+Calories block, then the nutrient groups as columns, minerals along the foot) once the container reaches 32rem, and the vertical panel below that — the fallback the FDA itself prescribes when horizontal space runs out. It needs no second DOM because **document order IS the vertical panel** (title → Calories → fats → carbs → minerals); the `@lg:` classes only re-arrange those same children. Never duplicate markup for the two layouts — a hidden second copy breaks every `getByText`.
- **The repeating rows are real `<table>`s — one per group.** Fats and carbs are independent, differently-sized lists rather than row-aligned pairs, so they don't share a table; the serving/Calories block stays plain divs (not repeating row data). Responsive grid/flex classes go **only on the plain-div wrappers around the tables**, never on a table-internal element — overriding `display` on `<table>`/`<tbody>`/`<tr>`/`<td>` strips their implicit table/row/cell roles in some browsers (notably Safari/VoiceOver). That's also why each mineral is its own single-row table: the flex wrapping happens *between* tables. Row hairlines rely on Tailwind Preflight's global `border-collapse: collapse`; overriding that in globals.css doubles them up. The row itself is `NutrientRowTr` in its own module with its own stories (the `Stat`/`ServingsInputCell` precedent) — don't fold it back in. It renders a bare `<tr>` and takes no `className` on purpose: the parent styles rows through its `<tbody>`, and its `@lg:` abbreviation swap resolves against the label's `@container`, so it shows full names anywhere outside one.
- **The breakpoint is a CONTAINER query, not a viewport one** (`@container` + `@lg:`). The label renders in a wide recipe page and a ~360px cooking-mode column *at the same viewport width*, so `lg:` would pick the wrong layout for one of them. If you suspect a variant isn't compiling, grep the built CSS for `@container (min-width:32rem)` — the `@lg:` utilities and the `@lg:[&>*…]` arbitrary variants land in **three separate blocks**, all correctly nested.
- **Row order is the FDA 2016 grouping** (fat, sat, unsat, cholesterol, sodium | carbs, fiber, sugars, protein). This deliberately replaced the vertical label's older custom order (fat, carbs, protein, then cholesterol/sodium): sharing one DOM means one order, and the FDA grouping is what makes the tabular columns split correctly.
- **No `%DV` column** — the app stores no daily values, and deriving them would state a nutritional recommendation it never sourced.
- **Only tracked nutrients are rendered — never an em dash.** A nutrient the source doesn't carry is omitted, and a group or minerals section that loses every row collapses *with its rule* (and, in tabular, its column — which is why the grid template is picked from the surviving block count via `GRID_COLUMNS`). Calories going absent takes the brand accent rule with it. This is a deliberate departure from the absent-≠-zero em-dash convention the rest of the nutrition UI uses (`NutritionDetail` still dashes): on a *label*, a column of dashes reads as broken rather than as "unknown".
- **Neither adapter emits rows its source can't fill.** `recipeNutritionRows` returns `micros: []` — the three minerals have no Schema.org slot (`SCHEMA_NUTRITION_MAP` drops them), so that path can never fill them. Don't "fix" this by widening `NutrientField`: only the ingredients view could ever supply them, so the label's field set would vary by source, fighting the all-or-nothing gate. Symmetrically the ingredient adapter omits the unsaturated-fat row (no catalog column). Because the two row sets now only partly overlap, the shared-wording test compares the **intersection** of keys.
- **The structure is the FDA's; the styling is the site's.** The regulation's heavy black bars and condensed black sans were dropped for warm tokens and serif-light display type. Three border tiers replace the 1/4/8px bars: `border-t-2 border-brand` on the Calories rule (the label's single accent), `border-t-2 border-border` on section rules, `border-t border-border` on row hairlines and tabular column dividers. Don't reintroduce `font-black` or `border-foreground` — hierarchy comes from size and spacing. Eyebrows use the site's `font-sans text-[10px] font-semibold uppercase tracking-widest text-muted-foreground` (the shared `EYEBROW` const). The label carries its own card frame standalone, and **NutritionPanel overrides it away** (`className="border-0 bg-transparent p-0"`) because the panel already supplies a frame and heading — nesting both reads as a double border.
- `servingCaption` is the label's "Serving size" prefix: passed by the drawer, **omitted** by the panel — `nutritionUnitLabel` is already a phrase, so a caption yields "Serving size: per 114 g serving".
- **The label renders no title of its own.** Both callers already put a heading immediately above it (the panel's "Nutrition" h2, the catalog drawer's "Label preview" h3), so a "Nutrition Facts" title only ever read as a duplicate — don't add one back. Tests key on the `"Amount per serving"` eyebrow to detect label view.
- Micro-gotchas: **Calories is the big display number and drops its unit** in both layouts, so tests assert `"520"`, not `"520 kcal"`; in label view `nutritionUnitLabel` renders **twice** (panel header + label serving line), so tests must use `getAllByText`. Coverage/naming is pinned in `src/__tests__/nutritionLabelRows.test.ts` (both adapters, against `NUTRIENT_FIELDS` and `NUTRITION_COLUMNS`).
